# 通学中事例の歯科医師レビュー判定基準

## 文書の状態

本書は、Excelによる2名独立評価のための**固定コードブック候補（研究者確認待ち）**である。研究責任者と評価を担当する歯科医師が、各定義、選択肢、境界例および解析目的との対応を確認し、版番号を付けて承認するまでは、開発用・最終評価用のいずれにも入力を開始しない。

承認後に開発用コードブックとして使用し、開発用100件の調停と誤り分析を終えた時点で改訂履歴を保存する。その後、最終評価用の版を凍結する。最終評価用100件を開いた後は、選択肢、定義または判定規則を変更しない。互換する自動分類器は現時点で未実装であり、本コードブックによる人手一致度評価とAI性能評価を混同しない。

## 1．目的と基本原則

通学中の事例で歯牙障害の構成割合が高かった背景を、事故原文から臨床的に確認する。複数ラベル語彙検出と旧単一自動分類は検索・監査用であり、人の正解を示すものではない。

評価者は次の原則を守る。

1. 歯牙障害区分、定型項目、自動回答、相手評価者の回答を見ず、割り当てられた原文だけで判定する。
2. 診断名、治療内容または歯牙損傷の重さから、原文にない受傷機転、接触対象、外力方向または保護具使用を推測しない。
3. 選択肢は本書に記載した文字列だけを使用する。独自表記、略語、同義語は入力しない。
4. 複数の出来事がある場合、起点となった出来事と、口腔・顔面へ最後に接触した対象を分けて記録する。
5. 情報不足時は推測せず、定められた「判定不能」を選ぶ。

## 2．空欄と欠測状態の区別

次の状態は意味が異なるため、相互に置き換えない。

| 状態 | 意味 | 入力完了として扱うか |
|---|---|---|
| 空欄 | まだ評価していない、または入力途中 | 扱わない |
| 判定不能 | 原文を最後まで確認したが、情報不足、曖昧さ、矛盾等により決められない | 扱う |
| 記載なし | 対象情報への言及が原文にない。事実として「なし」を意味しない | 扱う |
| なし（明記） | 「使用していなかった」等、否定内容が原文に明記されている | 扱う |
| 該当なし | その事例では項目自体が適用されない | 扱う |
| その他 | 十分な情報はあるが既定カテゴリ外 | コメント入力後に扱う |

Excelの必須欄には「未入力」という文字を入力せず、未着手・入力途中は空欄のままとする。提出時には必須欄の空欄を0件にする。「判定不能」「記載なし」「なし（明記）」「該当なし」は有効な判定値であり、空欄とは区別して解析する。

## 3．固定選択肢候補

### 3.1 起点機転（現行CSVの「主受傷機転」）

事故経過の中で、後続の接触や受傷につながった**最初の出来事**を1つ選ぶ。

ここでいう起点は最初の**物理的な事故事象**であり、その背景となる判断、回避行動または操作そのものではない。例えば、急ブレーキや衝突回避の後に接触なくバランスを失って倒れた場合は「転倒・つまずき」とする。先に他者・車両・構造物へ接触し、その後に倒れた場合は「衝突・接触」とする。

| 選択値 | 定義 |
|---|---|
| 転倒・つまずき | 歩行中または車両走行中にバランスを失う、つまずく、滑る等により、同一面へ倒れたもの |
| 衝突・接触 | 人、車両、構造物または物体との衝突・接触が転倒等より先に生じ、事故の起点となったもの |
| 転落・落下 | 階段、段差、高所等から高低差を伴って落下したもの |
| その他 | 起点を特定できるが上記3分類に含まれないもの。コメント必須 |
| 判定不能 | 起点の記載がない、複数機転の順序が不明、または記載が矛盾し特定できないもの |

判定例：

- 「バランスを崩して転倒し、顔面を路面に打った」：起点機転は「転倒・つまずき」。路面への接触を「衝突・接触」へ置き換えない。
- 「自動車と接触した後に転倒した」：順序が明記されていれば起点機転は「衝突・接触」。
- 階段で単につまずいて同じ段または踊り場へ倒れた記載は「転倒・つまずき」。上段から下段へ落ちたことが明記されれば「転落・落下」。高低差が分からなければ「判定不能」。
- 転倒語と衝突語があるが、どちらが先か分からない：起点機転は「判定不能」。キーワードの優先順位だけで決めない。

### 3.2 出来事の順序

| 選択値 | 定義 |
|---|---|
| 単一機転 | 判定に必要な出来事が1つだけ記載される |
| 複数機転・順序明記 | 複数の出来事があり、原文に前後関係が明記される |
| 複数機転・順序不明 | 複数の出来事があるが、前後関係を決められない |
| 判定不能 | 出来事の数または記載自体を判断できない |

「複数機転・順序不明」の場合、起点機転は原則「判定不能」とする。

### 3.3 最終接触対象（現行CSVの「衝突対象」）

口腔・顔面へ最終的に外力を与えた接触対象を1つ選ぶ。事故の起点となった対象とは限らない。

| 選択値 | 定義 |
|---|---|
| 路面・地面・床 | 道路、歩道、アスファルト、地面、校庭、床等 |
| 車両 | 自動車、二輪車、自転車等の車体。本人の自転車部品への接触は下記へ分ける |
| 自転車部品 | ハンドル、かご、フレーム、ペダル等、主に本人の自転車の部品 |
| 人 | 歩行者、同乗者、他の児童生徒等 |
| 構造物 | 壁、柱、塀、ガードレール、縁石、門扉等 |
| その他 | 接触対象を特定できるが上記に含まれないもの。コメント必須 |
| 該当なし | 口腔・顔面への接触対象が存在しないことが原文から明確なもの |
| 判定不能 | 接触対象の記載がない、複数候補から最終対象を決められない、または記載が曖昧なもの |

複数対象へ連続して接触した場合は、原文で順序が明確なときだけ最後の口腔・顔面接触対象を選ぶ。同時接触または順序不明なら「判定不能」とし、コメントへ候補を残す。部品名が具体的なら所有者を問わず「自転車部品」、単に自転車または車体とだけ記載される場合は「車両」とする。口腔・顔面への接触が明記されていない対象を、受傷結果から推測しない。

### 3.4 口腔・顔面への直接外力

| 選択値 | 定義 |
|---|---|
| あり（明記） | 口、歯、顔面、顎等が対象へ接触・強打したことが明記される |
| なし（明記） | 口腔・顔面への直接接触がなかったことが明記される |
| 記載なし | 直接外力の有無に関する記載がない |
| 判定不能 | 関連記載はあるが、口腔・顔面への直接外力かを決められない |

歯の破折、脱落、治療または補綴の記載だけでは「あり（明記）」にしない。

### 3.5 受傷部位

受傷部位は複数併存できるため、1つの複数選択セルにはせず、次の部位ごとに独立した列を設ける。

- 前歯部
- その他歯牙
- 歯牙・部位不明
- 口腔・口唇
- 顔面・顎
- その他部位

各部位列の選択値は次の3つに固定する。

| 選択値 | 定義 |
|---|---|
| 記載あり | 当該部位が原文に明記される |
| 記載なし | 当該部位への言及がない |
| 判定不能 | 部位への言及はあるが、当該分類に含まれるか決められない |

補足規則：

- 「記載あり」は、今回の事故による受傷部位として肯定的に記載された場合に限る。「前歯は打っていない」「顔面に異常なし」のような明示否定、単なる既往歴または無関係な語の出現は「記載あり」にしない。
- 診断・治療記載から部位が明確に特定できる場合は「記載あり」にできるが、そこから原文にない受傷機転、接触対象、外力方向を推測しない。
- 「前歯部」は永久歯・乳歯を問わず切歯と犬歯を含む。「その他歯牙」は小臼歯・大臼歯を含む。
- 「口腔・口唇」は口唇、舌、歯肉、頬粘膜、口蓋等を含む。「顔面・顎」は鼻、頬部、オトガイ、上顎・下顎等を含む。歯牙そのものはこれらに含めない。
- 「上顎前歯」は前歯部だけを「記載あり」とし、上顎骨・歯槽骨等の損傷が別に明記された場合だけ顔面・顎も「記載あり」とする。歯槽骨骨折は顔面・顎、歯肉損傷は口腔・口唇へ分類する。「口元」等で解剖学的分類を決められない場合は該当候補を推測せず「判定不能」とする。
- 「歯」「歯牙」のみで歯種・部位が不明な場合は「歯牙・部位不明」を「記載あり」とし、前歯部を推測しない。
- 前歯・臼歯等の具体的部位が記載され、同じ受傷を指す一般語の「歯」「歯牙」も併記されるだけなら、「歯牙・部位不明」は「記載なし」とする。別の部位不明歯牙受傷もある場合に限り併記し、コメントへ理由を残す。
- 前歯部と顔面・顎等が併記されていれば、それぞれを「記載あり」とする。
- 「その他部位」を「記載あり」とした場合は、コメントに部位を記載する。
- 受傷部位の集約状態は外部検査スクリプトで「1部位以上特定」「記載なし」「一部判定不能」「全体判定不能」として算出し、評価者が手入力しない。Excel内には計算式や外部リンクを置かない。

### 3.6 保護具

ヘルメットとマウスガードは別々の列で評価する。必要に応じて「その他保護具」を追加する。

| 選択値 | 定義 |
|---|---|
| 使用あり（明記） | 事故時に使用していたことが明記される |
| 使用なし（明記） | 事故時に使用していなかったことが明記される |
| 言及あり・使用状況不明 | 保護具への言及はあるが、事故時の使用状況を決められない |
| 記載なし | 保護具への言及がない。未使用とは解釈しない |
| 該当なし | 当該保護具の評価対象とならないことが原文から明確で、承認済みコードブックの適用条件を満たす |

「該当なし」を利用する対象条件は、コードブック承認時に研究者が確定する。条件が確定するまでは「記載なし」で代用せず、入力を開始しない。

### 3.7 予防可能性

本項目は原文に記載された修正可能要因の有無を評価するもので、事故が確実に防げたかを断定するものではない。

対象は、事故発生の回避だけでなく、口腔・顔面外傷の発生または重症度を軽減し得る要因を含む。ただし、原文に具体的事実がある場合だけ評価し、一般論として介入できそうだという推測は用いない。単なる速度の記載だけで「明記あり」とせず、速度超過、前方不注意、路面異常、操作上の問題または保護具不使用等が具体的に記載されたかを確認する。

| 選択値 | 定義 |
|---|---|
| 修正可能要因の明記あり | 速度、操作、路面、環境、行動、保護具等の具体的な修正可能要因が明記される |
| 修正可能要因の可能性あり | 修正可能要因が示唆されるが、原文だけでは確定できない |
| 修正可能要因の記載なし | 修正可能要因への言及がない。予防不能という意味ではない |
| 判定不能 | 記載が曖昧または矛盾し、上記3分類を決められない |

「修正可能要因の明記あり」または「修正可能要因の可能性あり」を選んだ場合、根拠区分を「行動」「路面・天候」「車両・操作」「施設・構造物」「保護具」「複数」「その他」から選ぶ。「その他」はコメント必須とする。該当しない場合の根拠区分は「該当なし」とする。

### 3.8 判定不能理由

いずれかの必須項目で「判定不能」を選んだ場合、主な理由を1つ選ぶ。

| 選択値 | 定義 |
|---|---|
| 該当なし | 判定不能項目がない |
| 原文情報不足 | 必要な記載が不足する |
| 時系列不明 | 複数出来事の順序が分からない |
| 複数候補 | 複数の候補から1つへ決められない |
| 用語が曖昧 | 表現の意味または指示対象が曖昧 |
| 対象外疑い | 通学中事例または評価対象として不適切な可能性がある |
| その他 | 上記以外。コメント必須 |

判定不能項目があるのに「該当なし」とすること、判定不能項目がないのに判定不能理由を入力することは禁止する。

## 4．コメント必須条件

次の場合はコメントを必須とする。

- いずれかの項目で「その他」を選んだ場合
- 判定不能理由が「その他」の場合
- 起点機転と最終接触対象の関係が通常の規則では説明できない場合
- 複数の別個の歯牙受傷があり、「歯牙・部位不明」と具体的歯牙部位を併記した場合
- 「対象外疑い」を選んだ場合

コメントは判断根拠を簡潔に記録し、原文にない氏名、施設名その他の識別情報を新たに追記しない。

## 5．入力矛盾と完了条件

Excel保存後に外部検査スクリプトで次の矛盾を検出し、解消するまで「入力完了」にしない。Excel内の計算式や外部リンクには依存しない。

1. 必須判定欄に空欄がある。
2. コードブック外の文字列が入力されている。
3. 「複数機転・順序不明」なのに、起点機転が「判定不能」以外で、説明コメントもない。
4. 直接外力が「あり（明記）」なのに、最終接触対象が「該当なし」である。
5. 直接外力が「なし（明記）」なのに、口腔・顔面の最終接触対象が具体的に選ばれている。
6. すべての部位列が「記載なし」なのに、部位集約状態が「1部位以上特定」になっている。
7. 具体的部位が1つ以上「記載あり」なのに、部位集約状態が「全体判定不能」になっている。
8. 予防可能性で修正可能要因を選んだのに、根拠区分が「該当なし」である。
9. 判定不能項目と判定不能理由の有無が一致しない。
10. コメント必須条件を満たすのにコメントが空欄である。

「入力状態」は外部検査スクリプトが「未入力」「入力途中」「入力完了」「要確認」として算出し、検査レポートへ出力する。評価者は直接変更しない。「判定不能」は入力完了値として扱う。Excelには状態判定用の数式や外部リンクを置かない。

## 6．開発、調停、凍結、最終評価

1. 研究者が本コードブック候補を確認し、開発用版番号を付けて承認する。承認前は入力を開始しない。
2. 開発用100件を評価者A・Bが別々のExcelで独立評価する。相手の回答、自動回答、歯牙障害区分は見ない。
3. 両者が100件を完了した後、元のA/B回答を読み取り専用で保存し、ハッシュを記録する。
4. 第三者が原文とA/B回答を確認し、不一致項目について合意値と調停理由を別の調停シートへ記録する。A/B原回答を上書きしない。
5. 開発用100件の一致例、不一致例および判定不能例を確認し、必要なコードブック改訂を変更履歴へ記録する。
6. 最終評価用コードブック、選択肢、入力仕様および矛盾検査実装を版番号・SHA-256付きで凍結する。
7. 開発用と重複しない最終評価用100件を、評価者A・Bが凍結版のまま独立評価する。最終評価中に定義や規則を変更しない。
8. 評価者間一致は調停前のA/B回答から算出し、調停後の合意値は将来のGold候補として固定する。
9. 判定不能例を黙って除外せず、全体件数、判定可能件数、判定不能件数および各精度指標の分母を明記する。
10. 互換する自動分類器、予測の事前封印、unblindおよび採点工程は未実装である。旧自動回答を性能評価へ流用せず、別工程の実装と事前凍結が完了するまで人手合意値と結合しない。

最終評価中に新たな曖昧例が見つかった場合は、規則をその場で変更せず、逸脱記録へ残す。最終評価結果を見て判定規則を再調整した場合、その100件は独立した最終評価標本として再利用しない。

## 7．情報管理と公開制約

- 原文、レビューID対応表、人手回答、コメント、調停記録、自動回答および歯牙障害区分は内部利用に限定する。
- `InternalReview/`および`Internal_DoNotPublish/`は所有者のみアクセス可能な状態を維持し、公開リポジトリ、投稿補足資料、外部AIまたは許可されていないクラウドサービスへ送らない。
- Excelのシート保護は誤編集防止であり、暗号化やアクセス制御の代替ではない。
- `AfterReview_DoNotOpen/`は、旧自動結果を含む隔離領域であり、人手評価と合意値固定の工程では開かない。将来、互換する自動分類器の評価工程を別途承認・実装した場合だけ、定めたunblind手順で使用する。
- 公開可能なのは、必要な小セル抑制と二次セル抑制を行った集計値のみとする。事例原文、内部ID、レビューID、自由コメント、個票単位の回答は公開しない。
- 旧単一自動分類、関連検定および図は使用停止のままとし、人手評価が終わるまで研究結果、抄録、発表または投稿原稿へ用いない。
