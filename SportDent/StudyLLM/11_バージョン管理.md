# バージョン管理

## 目的

LLM、プロンプト、カテゴリ辞書または検証規則が変わると、同じ文章でも結果が変わり得る。各解析結果を再現し、変更前後の性能を比較できるよう、実行単位で版を固定する。

## 必ず保存する版情報

| 対象 | 保存内容 |
|---|---|
| アプリ | Gitコミットまたはリリース版 |
| JSON Schema | `schema_version` |
| LLM | 提供者、モデル名、固定版、利用地域 |
| プロンプト | system・userテンプレートの版とハッシュ |
| 公式カテゴリ | 資料名、取得日、コード体系版 |
| 観測選択肢 | 対象期間、件数、ファイルハッシュ |
| 同義語候補 | 辞書版とハッシュ |
| 依存規則 | 規則版とハッシュ |
| 評価データ | 分割版、seed、重複グループ版、正解判定版 |
| 実行 | 日時、設定、件数、費用、応答時間、失敗率 |

## 変更時の規則

- モデル、プロンプト、辞書、依存規則のいずれかを変更したら新しい版を付ける。
- 最終評価データの結果を見て規則を変更した場合、そのデータを以後の未使用最終評価とは呼ばない。
- 公式カテゴリが変更された場合は、旧値から新値への移行表を作成する。
- 性能改善だけでなく、カバー率低下、特定カテゴリの悪化、null理由の変化を比較する。
- 本番反映前に`10_安全性試験ケース.csv`と固定回帰テストをすべて実行する。

## 実行記録の最小例

```text
run_id: 2026-08-11-001
app_version: 0.1.0
schema_version: 1.0.1
model: provider/model/fixed-version
prompt_version: prompt-001
category_version: category-001
synonym_version: synonym-001
rule_version: rule-001
evaluation_split: eval-001
```

APIキー、個人情報を含む原文、認証情報は版管理ファイルやGitへ保存しない。
