# StudyLLM再検討・修正記録

## 実施日

2026年8月11日

## 総合判断

「自由記述から既存DB項目の候補を抽出し、人が確認して登録する」という方向性は実現可能である。ただし、初期資料のままでは、欠損理由の混同、過剰な同義語置換、観測値を公式仕様とみなす誤り、評価バイアスが生じる可能性があったため修正した。

## 主な修正

1. プロジェクトを「LLMを一から作る」ものではなく、既存LLMを利用する構造化入力支援システムと明記した。
2. DB列名「災害発生時の状況」と画面表示名「事故発生時の状況」を区別した。
3. `null`を、未記載、曖昧、矛盾、非対応、検証棄却、非該当に分けた。システム障害は項目statusに混ぜず、トップレベルの`processing_status=error`、空の`fields`、保存停止として分離した。
4. 通学方法は場合別1が通学中の場合だけ、競技種目は所定の体育的場面の場合だけ候補を保持する規則を追加した。
5. 下位分類から上位分類を補完した値を、原文明記値と区別して記録する仕様にした。
6. 根拠文字列だけでなく原文上の開始・終了位置を必須とし、完全一致を機械検証する仕様にした。
7. 同義語辞書を「安全な自動置換」から「候補生成辞書」へ変更し、事故時点、本人、否定、別場面等の条件を追加した。
8. 解析データ内の観測値と、利用時点の公式入力値を区別した。
9. DB登録値を暫定ラベルとし、人の独立判定と調停で最終評価用正解を作る計画へ変更した。
10. 適合率98%を点推定だけで判断せず、片側95%信頼下限で評価する基準へ変更した。
11. JSON Schema、安全性試験ケース、版管理仕様を追加した。
12. 個人情報、外部API、ログ、権限、プロンプトインジェクション、XSSに関する実装開始条件を追加した。
13. JSON Schemaを1.0.1へ更新し、処理障害時の`fields`を空に固定して部分結果の保存を禁止した。
14. LLMが他者の活動場所・競技・遊具を被災者の値に誤帰属する事例に対し、人物文脈の決定論的検証と回帰試験T015を追加した。
15. LLMが棄却した「登校中」等の明確な値を辞書・階層規則で回復できるよう、決定論的規則をLLMより優先するハイブリッド構成にした。
16. 公開デモ用に、署名付き期限セッションによるログイン、新規登録・DB閲覧メニュー、確定保存済みデータの一覧画面を追加した。
17. 同一文の被災者と観察対象に異なる学校種・学年が記載される場合に、被災者の主語を優先し、「弟を見ていた」等の対象人物の属性を除外する回帰試験を追加した。

## データ監査で確認した事項

- 場合別・発生場所の観測組合せと件数は既存集計に一致した。
- 通学方法の非欠損590件はすべて場合別1が通学中だった。
- 競技種目の非欠損3,923件は、体育的部活動、体育、競技大会・球技大会、体育的クラブ活動のいずれかだった。
- 校舎外―遊戯室の1件は原文との不一致が疑われ、固定規則から除外した。
- 「準備運動等」「自転車競技部」「公園」等の1件値は、正式カテゴリではなく表記・登録揺れの可能性がある。

## 現在も未確定の事項

- 利用時点の公式カテゴリ体系と固定カテゴリID
- 対象を歯牙障害に限定するか、全傷害とするか
- 外部API利用の可否と匿名化・保持方針
- 単独利用か複数人利用か
- 未使用の最終評価データの確保方法
- nullのまま保存可能な項目と、確認画面の必須項目

これらを決定するまでは、本番用アプリ開発や実事故文の外部API送信へ進まない。
